# reprooo-app
A web application that turns an unstructured discussion (a Slack thread for example) into a ready-to-use bug report/task draft based on a template.
Reprooo — веб-приложение, которое превращает неструктурированное обсуждение (например, тред из Slack) в готовый черновик баг-репорта по шаблону тестировщиков. Сейчас обсуждения проходят в тредах, а тикет в Jira тестировщик собирает вручную, каждый раз копируя контекст в нейросеть. Продукт убирает эту ручную работу и добавляет то, чего нет в обычном чате: шаблон баг-репорта зашит в приложение, поэтому результат всегда в одном формате и не зависит от навыков промптинга, а приложение явно показывает, каких данных не хватает (шаги воспроизведения, ожидаемый результат, окружение), и готовит текст уточняющих вопросов для возврата в тред.

Работает это так: пользователь вставляет текст обсуждения, приложение маскирует чувствительные данные (имена, email, названия сервисов, идентификаторы; ключи и пароли вырезаются полностью) и показывает пользователю замаскированный текст перед отправкой. LLM возвращает структурированный черновик по схеме шаблона, правила полноты проверяются в коде, после чего оригинальные данные подставляются обратно из словаря, который живёт только в памяти сессии. Человек правит черновик с подсвеченными пропусками и по кнопке создаёт тикет в Jira Cloud (в рамках хакатона через мок, реальная интеграция описывается как следующий шаг). Шаблон режима задаётся конфигом, поэтому новый формат можно добавить без разработки.

Измеримый эффект: меньше времени на оформление тикета и меньше возвратов на доработку, а за счёт сбора метрик (сколько полей правят вручную, какие чаще пропускают) его можно подтвердить цифрами. 

Путь развития: интеграция со Slack («создать тикет из треда»), поиск дублей по реальной базе, использование одобренной компанией модели вместо внешнего провайдера, а затем второй режим «запись о решениях» — сборка из разрозненных источников (Jira, заметки, треды) списка договорённостей с владельцами, сроками и неподтверждёнными пунктами, по образцу ролей и follow-up из Rootly. Для хакатона вся работа выполняется на синтетических данных без использования конфиденциальной информации.
